# 설비 부품 교체 관리 시스템 (EquipDoctor)

설비 → 유닛 → 부품 계층 구조로 교체 주기를 관리하고, 교체 시기를 자동으로 알려주는 사내용 웹 애플리케이션.
Flask + SQLite 기반이며, 설치 과정 없이 바로 실행할 수 있는 단일 파일 배포판도 함께 제공한다.

## 배포 형태

기능은 동일하고, 목적에 따라 두 가지 형태로 제공된다.

| 구분 | 파일 | 용도 |
|---|---|---|
| 모듈 버전 | `app.py` + `templates/` + `static/` | 개발·유지보수용. 코드를 수정하며 작업할 때 사용 |
| 단일파일 배포판 | `설비부품교체관리_단일파일.py` | 위 세 가지를 하나로 합친 배포용 파일. 현장 PC에 파일 하나만 복사해 바로 실행 |
| 실행기 | `실행.bat` | 단일파일 배포판을 더블클릭으로 실행. 실행 시 포트 번호를 입력받음(기본값 5000) |

단일파일 배포판은 `build_single_file.py`(리포지토리에는 포함되지 않은 빌드 스크립트)로 모듈 버전을 합쳐서 생성하며, 두 버전은 항상 동일한 기능을 유지하도록 함께 관리한다.

## 기술 스택

- **Backend**: Python 3 + Flask
- **DB**: SQLite (WAL 모드, `synchronous=NORMAL` 등 성능 튜닝 PRAGMA 적용)
- **Frontend**: 바닐라 JS + Bootstrap 5(CDN) + Bootstrap Icons
- **기타 라이브러리**: `python-pptx`(PPT 내보내기), `requests`(사내 메일 API 연동), `werkzeug`(비밀번호 해시)

## 폴더 구조

```
app.py                       # 메인 백엔드: 라우트, DB 스키마/마이그레이션, 비즈니스 로직
설비부품교체관리_단일파일.py    # app.py + templates + static를 하나로 합친 배포판
실행.bat                     # 단일파일 배포판 실행기 (포트 입력)
requirements.txt             # 모듈 버전 실행에 필요한 패키지 목록
equipment.db                 # SQLite DB (최초 실행 시 자동 생성, 이후 자동 마이그레이션)
templates/                   # 13개 페이지 HTML (Jinja2)
static/                      # 페이지별 JS + 공통 style.css, theme.js
```

## 화면 구성

| 경로 | 페이지 | 설명 |
|---|---|---|
| `/` | 설비 대시보드 | 전체 설비를 캔버스에 배치해 한눈에 보여줌 (드래그로 재배치) |
| `/equipment/<id>` | 설비 상세 | 설비에 속한 유닛들을 캔버스에 배치, 도면 첨부 |
| `/unit/<id>` | 유닛 상세 | 유닛에 속한 부품 배치, 교체일 기록, 도면/메모 관리 |
| `/alerts` | 전체 교체 현황 | 교체 필요/임박 목록 + 상태별 색상의 캘린더 뷰(최대 6개월) |
| `/search` | 부품 검색 | 이름/상태/설비로 검색, 결과 페이지네이션 |
| `/stats` | 통계 | 부품/유닛별 비용 통계, CSV·PPT 내보내기 |
| `/inventory` | 재고 관리 | 부품 재고·안전재고·구매처·리드타임 관리 |
| `/bulk-add-parts` | 부품 일괄 등록 | 엑셀에서 복사한 표를 붙여넣어 여러 부품을 한 번에 등록 |
| `/config` | 기본 유닛 구성 | 모든 설비에 공통으로 쓰이는 유닛 템플릿 관리 |
| `/rollout` | 횡전개 현황판 | 엑셀 표를 붙여넣으면 진행 현황 게이지를 자동 계산 |
| `/trash` | 휴지통 | 삭제된 설비/유닛/부품 개별 또는 일괄 복원·영구 삭제 |
| `/activity-log` | 변경 이력 | 생성/수정/삭제/복원 이력 (14일 지난 기록은 자동 정리) |
| `/login` | 로그인 | 이름 + 공용 비밀번호 인증 |

## 데이터베이스 구조

SQLite 파일 하나(`equipment.db`)에 아래 16개 테이블이 들어있다. 앱 실행 시 `init_db()`가 없는 테이블/컬럼을 자동으로 만들고 필요한 마이그레이션을 수행한다.

| 테이블 | 역할 |
|---|---|
| `equipments` | 설비 목록 (이름, 아이콘, 위치, SETUP일 등) |
| `units` | 설비에 속한 유닛(하위 구성 요소) |
| `parts` | 유닛에 속한 부품 (교체 주기, 재고, 구매처 등) |
| `drawing_blobs` | 도면 이미지 원본. 내용(SHA256 해시) 기준으로 중복 제거 저장 |
| `replacement_history` | 부품 교체 이력 (날짜, 비용, 비고) |
| `equipment_notes` / `unit_notes` | 설비/유닛별 자유 메모 |
| `unit_templates` | "기본 유닛 구성" 화면에서 관리하는 공통 유닛 템플릿 |
| `master_backup_units` / `master_backup_parts` | 기준 설비(TEAG01호기) 구성 스냅샷. "전체 설비에 적용" 시 이 스냅샷을 기준으로 동기화 |
| `bulk_part_entries` / `bulk_part_entry_units` | 부품 일괄 등록(붙여넣기) 임시 데이터 |
| `rollout_items` | 횡전개 현황판에 붙여넣은 표(HTML) 저장 |
| `mail_recipients` | 상태 리포트 메일 수신자 목록 |
| `activity_log` | 변경 이력 로그. 14일 지난 기록은 매일 자동 정리 |
| `app_config` | 비밀번호 해시, 세션 secret key, 메일 예약 시간 등 앱 설정 값 |

## 핵심 기능

- **시각적 배치**: 설비/유닛/부품을 캔버스 위에 드래그로 자유 배치, 크기 조절
- **교체 주기 자동 판정**: 마지막 교체일 + 주기로 상태(정상/임박/필요)를 계산해 색으로 표시
- **캘린더 뷰**: 월별 교체 예정일을 달력으로 확인 (오늘 기준 최대 6개월 뒤까지)
- **기준 설비 동기화**: 기준 설비(TEAG01호기, `MASTER_EQUIPMENT_ID`)의 구성을 백업해 나머지 19개 설비(`EQUIPMENT_COUNT`)에 일괄 적용
- **도면 첨부 + 중복 제거**: 부품/유닛에 도면 이미지를 붙여넣기로 첨부, 동일 도면은 내부적으로 한 번만 저장
- **재고 관리**: 안전재고 이하 시 알림, 구매처·리드타임 관리
- **검색/통계**: 조건별 검색(페이지네이션), 비용 통계, CSV/PPT 내보내기
- **메일 자동 발송**: 지정한 시각에 설비 현황 리포트를 메일로 자동 발송
- **백업/복원**: DB 파일 다운로드, 휴지통을 통한 개별·일괄 복원 및 영구 삭제
- **변경 이력 추적**: 모든 생성/수정/삭제/복원 작업을 기록 (오래된 기록은 자동 정리)
- **포트 지정 실행**: 같은 컴퓨터에서 다른 설비군용으로 폴더를 복사해 다른 포트로 여러 인스턴스 동시 운영 가능

## 실행 방법

**단일파일 배포판 (권장, 설치 불필요)**
1. `설비부품교체관리_단일파일.py`와 `실행.bat`을 같은 폴더에 둔다
2. `실행.bat`을 더블클릭 → 포트 번호 입력(Enter 시 5000) → 자동 실행
3. 브라우저에서 `http://localhost:포트번호` 접속

**모듈 버전 (개발용)**
```bash
pip install -r requirements.txt
python app.py           # 기본 포트 5000
python app.py 5001      # 포트 지정 실행
PORT=5001 python app.py # 환경변수로 포트 지정
```

## 계정

- 로그인 시 이름은 자유 입력, 비밀번호는 전체 공용 비밀번호 1개
- 최초 비밀번호: `0000` (로그인 후 대시보드에서 변경 권장)
